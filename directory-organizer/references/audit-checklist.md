# 审计核查清单

路径修正完成后，根据整理范围派 2-3 个分殿并行核查。

## 分殿分工模板

根据用户的实际环境动态调整检查项，以下为通用模板：

### 分殿 1：定时任务 + 系统服务

先了解用户环境的任务调度方式，然后逐项检查：

- 系统 crontab（`crontab -l`）：每个脚本是否存在、脚本内路径是否可达
- 第三方调度工具（如 cc-connect cron、pm2、supervisor 等）：所有任务的 prompt/命令中是否有旧路径
- systemd 服务（`systemctl list-units --type=service`）：关键服务是否 running，`WorkingDirectory`、`ExecStart` 路径是否正确
- 应用内调度（如 Claude Code scheduled_tasks.json）：任务路径是否有效

### 分殿 2：项目完整性 + 路径引用

- 各项目目录的 `.git/config` remote 是否正常
- `package.json`、`docker-compose.yml`、`Makefile` 中是否有旧绝对路径
- 项目 README.md 中的路径描述是否与实际一致
- 迁移后的目录是否完整（对比迁移前后）
- 是否有残留的空目录、过期副本、临时文件

### 分殿 3：配置文件 + 记忆/文档

- 项目级 CLAUDE.md 和 settings 文件中的路径
- 用户记忆/知识库文件中的路径（如 `.claude/projects/*/memory/`）
- 插件配置文件中的路径
- hooks 脚本中的路径
- Shell 配置文件（`.bashrc`、`.profile`、`.zshrc`）中的路径引用

## 搜索关键词

给每个分殿一份需要搜索的旧路径列表。从变更清单的"源"列提取：
- 所有移动过的目录的旧路径
- 所有删除过的目录的路径
- 如果是从其他用户迁移过来的，旧用户的家目录路径（如 `/root/` → `/home/xxx/`）

## 审计报告格式

```
## 审计报告：<范围>

### 发现的问题
| 文件 | 行号 | 问题 | 严重程度 | 建议修正 |
|------|------|------|---------|---------|
| ... | ... | ... | 严重/中等/低 | ... |

### 已确认正常
- 逐项列出验证通过的检查项

### 总结
- ✅ 正常：X 项
- ⚠️ 需注意：Y 项
- ❌ 需修复：Z 项
```

## 处理优先级

- 严重和中等问题 → 立即修复
- 低优先级问题 → 记录在最终报告中，不阻塞流程
- 纯历史记录（日志文件、会话存档）中的旧路径 → 可忽略
